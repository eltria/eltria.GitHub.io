02

RSS 服务器

eltria/rss
CSlidingWindow 缓存
内存上限 512MB，尾部淘汰最旧文章。60 秒增量刷新仅加载新文章，预排序供 Fever 二分查找分页。Feed 单遍分桶预渲染 + gzip + ETag。
FFever API 协议
兼容 Reeder / NetNewsWire 等 RSS 客户端。html 字段组装: summary + <hr> + content_markdown，支持 since_id 增量分页。
Q核心查询
优先读取 content_markdown，fallback 到 cleaned_content。仅查询 status=completed 且未删除的文章。
M性能指标
无锁原子环形缓冲区延迟直方图，暴露 P50/P95/P99 端点。<5ms 响应时间，不对数据库造成读压力。

03

Morning Brief 服务

eltria/moning-brief
FFetcher 采集
双源采集: RSS Fever API (5min 周期, since_id 增量) + Tavily Search (3h 周期, include_raw_content)。SHA256(URL) 去重，Valkey Set 存储，7 天 TTL。
PProcessor 处理
CJK 比例语言检测 → 外文全文翻译 (GLM-5.1, 16K tokens) → 5 篇批量摘要 + 分类 (16 类)。HTML 清洗 + 截断，限流 1 req/3s。

06

关键设计决策

三服务分离News(采集) / RSS(缓存) / Brief(消费) 职责清晰，独立扩展，通过 PostgreSQL 解耦
PostgreSQL 数据总线News 写入、RSS 读取，避免服务间直接耦合，Supabase 托管降低运维成本
Fever API 协议兼容 Reeder、NetNewsWire 等现有 RSS 客户端，同时作为 Morning-Brief 的数据桥梁
内存缓存 + 预渲染RSS 服务器 <5ms 响应，SlidingWindow 512MB 上限，不对数据库造成读压力
两阶段评分Phase1 确定性评分保证速度和稳定性，Phase2 LLM 评分提升精度
不对称反馈 -3 vs +2负面体验代价更高，快速降权差内容，正向激励温和避免刷分
CJK 比例语言检测不依赖 fetcher 标记，由实际内容 CJK 字符比例决定
content_markdown 优先比 cleaned_content 完整，保留文章结构和格式化信息
Valkey Sorted Set 新闻池天然按分数排序，6h TTL 自动过期，组装摘要时保证类目多样性
API Key 轮换 + 月度预算多 Tavily Key 自动切换 + 月度用量追踪，避免超额
